同一個問題,依「X 是什麼」分岔成三條完全不同的路徑。本次全部實測
我已經有 ___,想併進 VCF 9.1.1 管理網域
X = VCF Operations
(含它附帶的 License Server)
✅ UI 精靈原生支援
Plan → Step 1 Existing Component

spec:"useExistingDeployment": true

X = vCenter + 它的 vSphere 叢集
✅ 同一條路,而且是強制的
同一頁勾「I have an existing vCenter instance」
🔒 只要勾了既有 Operations,這一項會自動勾選並鎖住 —— 精靈強制管理網域的 vCenter 必須是 Operations 所在的那一台
destination cluster = 跑著 vCenter appliance 的那個叢集,不能另選
既有叢集的主機/VDS/vSAN 全部沿用,不必是乾淨主機
部署里程碑:Convert the existing vCenter to a new VCF instance(42 個子任務)
X = 只有一堆 ESXi 主機
(沒有既有 vCenter / Operations)
⚠ 走 greenfield,要乾淨主機
Existing Component 什麼都不勾
Prepare 變成 9 步,多出 Hosts / Storage / Distributed Switch
主機必須是乾淨的,六項檢查見圖 3
既有叢集餵進來會六項全掛
想把既有 vSphere 叢集變 workload domain(不是管理網域),走 VCF Operations 的 Import a vCenter
關鍵:開關在 Plan 階段,不在 Prepare 階段
精靈分成 Introduction → Plan → Prepare → Deploy 四個階段。 「要不要用既有元件」是在 Plan 的第 1 步決定的,決定完之後 Prepare 的步數與欄位會整個跟著變。 Plan 這一步跳過的話,Prepare 就是純 greenfield 的 9 步,對既有環境一定過不了驗證。
Plan → Step 1  Existing Component [v] I have an existing VCF Operations 9.1 instance [v] I have an existing vCenter instance ← 自動勾選 + DISABLED [ ] The vCenter instance is registered with NSX Manager [v] I have an existing VCF Automation instance or I will deploy later
Prepare 階段Greenfield(什麼都不勾)Converge(勾既有 Operations + vCenter)
步數9 步6 步
