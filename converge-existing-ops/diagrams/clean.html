圖 3 — Greenfield 路徑對「乾淨主機」的六項要求

⚠ 只在 Plan → Existing Component 什麼都不勾(greenfield)時適用。把既有叢集餵進這條路,16 項驗證中有 4 項失敗 —— 下表是實測回傳的錯誤碼。
勾了「既有 Operations / vCenter」走 converge 的話,這六項檢查整組不會執行(見圖 2)。

Network Configuration
IP_NOT_IN_USE		 ✓所有要部署元件的 IP 都還沒被佔用 ✗既有 vCenter 就在那個 IP 上
"IP 10.0.1.60 allocated for vcf-m03-vc01.home.lab is already in use"
前六項講的是同一件事:Deployment Wizard 是 greenfield 工具,它要的是剛裝好、什麼都沒設定的 ESXi。
最後一項 IP_NOT_IN_USE 是另一回事 —— 在 greenfield 路徑下,填既有元件的 FQDN 只會讓精靈以為那是「要新部署的目標」, 看到 IP 被佔用就報錯。要讓它認得既有元件,必須回到 Plan → Existing Component 勾選。
所以怎麼辦 ·  ① 這六項只擋 greenfield 路徑。既有叢集要變管理網域,正解是在 Plan 階段勾「既有 vCenter」走 converge,不是把主機洗乾淨。
② useExistingDeployment 不必手動改 JSON —— Plan 階段勾選後精靈會自己設成 true。
③ 走 converge 時 License Server 連填都不用填 —— 既有 Operations 已經接著它,精靈直接繼承。
