階段 1converge

既有 vSphere → VCF 9.1.1 管理網域 vcf-m02

VCF Installer 9.1.1 · workflowType: VCF · 既有 vCenter useExistingDeployment: true

階段 2建來源端

另建一套獨立 vSphere(沒有被任何 SDDC Manager 納管)

vcf-w01-vc01 8.0.3 + ESXi 8.0 U3b ×3 + vSAN 1500 GB
刻意做成「客戶現場」的樣子,用 vcsa-deploy 單節點 vSAN 引導再補齊叢集
3 台主機 · vSAN 1500 GB
只動 vCenter,主機完全不碰
階段 3升 vCenter

vCenter 8.0.3 → 9.1.1(migration-based)

範本用 embedded_vCSA_on_VC.json(透過 vCenter 部署,才接得上 VDS static-binding portgroup)
部新 appliance 拿臨時 IP → 匯出資料 → 舊的關機 → 新的接管原 FQDN/IP　三台主機維持 ESXi 8.0 U3b
Upgrade finished successfully　50 分鐘
★ 為什麼一定要升:NSX 9.1 不支援 vCenter 8.0 U3a 以後的版本
階段 4匯入

VCF Operations → Add workload domain → Import a vCenter

入口不在 VCF Installer(workflowType: VCF_EXTEND 是「VVF 補成 VCF」,不是匯入)
精靈第 2 頁把 NSX Manager VIP 指向管理網域正在用的 vcf-m02-nsx01 → 這就是共用 NSX
precheck 第一輪 68 Passed / 3 Errors / 4 Warnings 修完第二輪 71 / 0 / 1 → 匯入 57 / 57,約 15 分鐘
🔴 共用 NSX ≠ 主機自動被 prep。匯入只建立「網域 ↔ NSX 執行個體」的歸屬關係; w01 的主機沒有變成 host transport node,transport node collection 仍只有管理網域那一個。
